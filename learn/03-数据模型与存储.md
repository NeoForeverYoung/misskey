# Misskey 数据模型与存储

Misskey使用PostgreSQL作为主要数据库，结合TypeORM框架实现对象关系映射。本文档将详细介绍Misskey的数据模型设计和存储机制。

## 数据库技术栈

Misskey的数据存储层由以下技术组成：

1. **PostgreSQL** - 主要关系型数据库
2. **TypeORM** - 对象关系映射框架
3. **Redis** - 用于缓存和实时特性支持
4. **Bull** - 基于Redis的队列系统，用于异步任务

### 关系设计

Misskey使用TypeORM提供的关系装饰器定义实体间关系：

1. **一对多关系** - 例如用户和帖子：
   ```typescript
   @ManyToOne(type => MiUser, {
       onDelete: 'CASCADE',
   })
   @JoinColumn()
   public user: MiUser | null;
   ```

2. **多对多关系** - 例如用户和用户列表：
   ```typescript
   // 使用中间表实现多对多关系
   @Entity('user_list_membership')
   @Index(['userId', 'userListId'], { unique: true })
   export class MiUserListMembership {
       // ...
   }
   ```

## 仓库模式

Misskey使用仓库模式访问数据库，所有仓库都在`RepositoryModule`中定义并通过依赖注入使用：

```typescript
const $notesRepository: Provider = {
    provide: DI.notesRepository,
    useFactory: (db: DataSource) => db.getRepository(MiNote).extend(miRepository as MiRepository<MiNote>),
    inject: [DI.db],
};
```

仓库使用示例：

```typescript
@Injectable()
export class MyService {
    constructor(
        @Inject(DI.notesRepository)
        private notesRepository: NotesRepository,
    ) {}

    async findNote(id: string) {
        return this.notesRepository.findOneBy({ id });
    }
}
```

### 自定义仓库方法

Misskey通过`miRepository`对象扩展了标准仓库功能：

```typescript
export const miRepository = {
    // 插入并立即获取一个实体
    async insertOne(entity, findOptions?) {
        const opt = this.manager.connection.options as PostgresConnectionOptions;
        if (opt.replication) {
            const queryRunner = this.manager.connection.createQueryRunner('master');
            try {
                return this.insertOneImpl(entity, findOptions, queryRunner);
            } finally {
                await queryRunner.release();
            }
        } else {
            return this.insertOneImpl(entity, findOptions);
        }
    }
    // ... 其他扩展方法
};
```

## 数据迁移

TypeORM处理数据库模式迁移：

```typescript
// 迁移配置
migrations: ['../../migration/*.js']
```

迁移文件定义了数据库变更：

```typescript
export class AddColumnToUser1234567890123 implements MigrationInterface {
    name = 'AddColumnToUser1234567890123';

    public async up(queryRunner: QueryRunner): Promise<void> {
        await queryRunner.query(`ALTER TABLE "user" ADD "newColumn" varchar(128)`);
    }

    public async down(queryRunner: QueryRunner): Promise<void> {
        await queryRunner.query(`ALTER TABLE "user" DROP COLUMN "newColumn"`);
    }
}
```

## 数据访问优化

### 非标准化字段

为了减少关联查询，Misskey在某些模型中使用了非规范化字段：

```typescript
//#region Denormalized fields
@Index()
@Column('varchar', {
    length: 128, nullable: true,
    comment: '[Denormalized]',
})
public userHost: string | null;

@Column({
    ...id(),
    nullable: true,
    comment: '[Denormalized]',
})
public replyUserId: MiUser['id'] | null;
//#endregion
```

### 索引优化

使用适当的索引提高查询性能：

```typescript
@Index(['userId', 'id'])
@Entity('note')

@Index()
@Column({...})
public replyId: MiNote['id'] | null;
```

### 主从复制支持

Misskey支持数据库主从复制，提高读取性能：

```typescript
replication: {
    master: {
        host: config.db.host,
        port: config.db.port,
        username: config.db.user,
        password: config.db.pass,
        database: config.db.db,

    slaves: config.dbSlaves!.map(rep => ({
        host: rep.host,
        port: rep.port,
        username: rep.user,
        password: rep.pass,
        database: rep.db,
    })),
},
```

## 小结

Misskey的数据模型设计结合了关系数据库的结构化存储和现代ORM的灵活性，通过以下特点实现了高效的数据管理：

1. **类型安全** - 使用TypeScript和TypeORM提供完整的类型安全
2. **关系建模** - 清晰定义实体间关系和约束
3. **非规范化** - 适当的字段非规范化提高查询性能
4. **缓存** - Redis缓存减少数据库负载
5. **实体转换** - 分离存储和表示层，增强灵活性

理解这些数据模型和存储机制对于Misskey的二次开发和修改至关重要，也为其他基于TypeORM的项目提供了良好的参考。
