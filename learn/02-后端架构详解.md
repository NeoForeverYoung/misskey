# Misskey 后端架构详解

Misskey的后端使用Node.js和TypeScript构建，采用NestJS框架提供依赖注入和模块化结构。本文档将详细介绍Misskey后端的代码组织和主要模块。

## 后端目录结构

Misskey的后端代码位于`packages/backend/src`目录下，主要组织如下：

```
src/
├── config.ts                  # 配置文件定义和加载
├── const.ts                   # 常量定义
├── di-symbols.ts              # 依赖注入的符号定义
├── GlobalModule.ts            # 全局模块定义，包含应用级别依赖项配置
├── index.ts                   # 应用入口点
├── boot/                      # 启动过程相关代码
├── config/                    # 配置模块和配置类型定义
├── core/                      # 核心服务和业务逻辑
│   ├── activitypub/           # ActivityPub协议相关实现
│   ├── chart/                 # 图表和数据统计
│   ├── entities/              # 实体服务，处理数据包装和转换
│   └── ... 其他核心服务
├── models/                    # 数据模型定义
│   ├── entities/              # 实体类定义
│   ├── json-schema/           # JSON Schema定义
│   ├── repositories/          # 仓库层定义
│   ├── _.ts                   # 模型索引文件
│   └── ... 具体模型文件
├── misc/                      # 杂项工具函数
├── postgres.ts                # PostgreSQL数据库连接配置
├── queue/                     # 任务队列相关
├── remote/                    # 远程交互相关代码
├── server/                    # 服务器和API相关代码
│   ├── api/                   # API端点和服务
│   │   ├── endpoints/         # 所有API端点定义
│   │   ├── SigninApiService.ts # 登录API服务
│   │   ├── SignupApiService.ts # 注册API服务
│   │   └── ... 其他API服务
│   ├── web/                   # Web服务相关
│   ├── ActivityPubServerService.ts # ActivityPub服务器服务
│   └── ... 其他服务器组件
├── services/                  # 服务实现
└── types.ts                   # 类型定义
```

## 关键模块详解

### 1. 核心服务 (`core/`)

`core/`目录包含了Misskey的核心业务逻辑实现，是后端最重要的部分：

#### 实体服务 (`core/entities/`)

实体服务负责将数据库实体转换为前端可用的格式：

- `NoteEntityService` - 处理帖子(Note)实体
- `UserEntityService` - 处理用户实体
- `DriveFileEntityService` - 处理文件实体

这些服务通常包含`pack`方法，将数据库记录转换为前端可用的JSON结构，添加必要的计算字段并移除敏感信息。

#### ActivityPub (`core/activitypub/`)

实现联邦协议，使Misskey能与其他联邦宇宙实例交互：

- `ApRendererService` - 将Misskey实体渲染为ActivityPub格式
- `ApDeliverManagerService` - 管理ActivityPub内容分发
- `ApResolverService` - 解析远程ActivityPub内容

#### 核心功能服务

核心业务逻辑的实现：

- `NoteCreateService` - 帖子创建服务
- `UserFollowingService` - 用户关注关系服务
- `DriveService` - 文件存储服务
- `NotificationService` - 通知服务

### 2. 数据模型 (`models/`)

数据模型定义了应用的数据结构和数据库表映射：

- 每个实体类代表一个数据库表
- 使用TypeORM注解定义字段和关系
- 包含数据库迁移和模式定义

主要模型包括：

- `MiUser` - 用户模型
- `MiNote` - 帖子模型
- `MiDriveFile` - 文件模型
- `MiFollowing` - 关注关系模型

### 3. API端点 (`server/api/endpoints/`)

API端点处理HTTP请求，实现REST API功能：

```
endpoints/
├── admin/        # 管理员API
├── auth/         # 认证相关API
├── drive/        # 文件存储API
├── federation/   # 联邦功能API
├── i/            # 用户自身相关API
├── meta/         # 元数据API
├── notes/        # 帖子相关API
├── users/        # 用户相关API
└── ... 其他API类别
```

每个端点文件通常包含：
- `meta` - 元数据定义（权限要求、响应格式等）
- `paramDef` - 参数定义和验证规则
- 端点类实现，通常继承自`Endpoint`基类

### 4. 仓库层 (`RepositoryModule`)

使用仓库模式访问数据库：

```typescript
const $notesRepository: Provider = {
    provide: DI.notesRepository,
    useFactory: (db: DataSource) => db.getRepository(MiNote).extend(miRepository as MiRepository<MiNote>),
    inject: [DI.db],
};
```

这些仓库提供了数据访问抽象，通过依赖注入使用。

### 5. 依赖注入系统

Misskey使用NestJS的依赖注入系统管理组件依赖：

```typescript
// 定义依赖注入符号
export const DI = {
    config: Symbol('config'),
    db: Symbol('db'),
    redis: Symbol('redis'),
    usersRepository: Symbol('usersRepository'),
    notesRepository: Symbol('notesRepository'),
    // ...其他符号
};

// 注入依赖
constructor(
    @Inject(DI.notesRepository)
    private notesRepository: NotesRepository,

    @Inject(DI.usersRepository)
    private usersRepository: UsersRepository,

    private noteEntityService: NoteEntityService,
) {
    // ...
}
```

### 6. 服务器配置 (`server/`)

处理HTTP和WebSocket请求：

- `server/api/ApiServerService.ts` - API服务器设置
- `server/web/WebServerService.ts` - 静态文件和前端服务
- `server/ActivityPubServerService.ts` - ActivityPub协议服务器

### 7. 队列系统 (`queue/`)

使用Bull队列处理异步任务：

- 联邦内容分发
- 长时间运行的任务
- 定时任务

## 技术特性

### NestJS框架

Misskey使用NestJS框架，提供了：

- 依赖注入系统
- 模块化结构
- 面向切面编程
- 声明式元数据

### TypeORM

使用TypeORM进行对象关系映射：

- 实体定义
- 仓库模式
- 迁移支持
- 关系处理

### Redis

Redis用于：

- 缓存
- 会话存储
- 实时更新
- 队列支持

## 代码流程示例

### 帖子创建流程

1. 请求到达 `notes/create` 端点
2. 端点验证参数并调用 `NoteCreateService.create()`
3. 创建服务处理业务逻辑（内容处理、权限检查等）
4. 调用 `insertNote()` 方法将帖子插入数据库
5. 处理后续任务（通知、时间线更新等）
6. 返回结果给客户端

## 最佳实践

Misskey后端展示了几个值得学习的最佳实践：

1. **关注点分离** - 将不同功能拆分为独立模块
2. **依赖注入** - 使用DI管理组件依赖
3. **仓库模式** - 抽象数据访问逻辑
4. **服务层** - 封装业务逻辑
5. **实体转换** - 分离数据库模型和API响应格式

## 小结

Misskey的后端架构采用了现代化的设计原则，通过模块化、依赖注入和分层设计实现了高度可维护和可扩展的代码结构。理解这种架构有助于进行Misskey的二次开发和定制，也为其他Node.js项目提供了良好的参考。
