# Misskey 本地部署与调试指南

本文档将指导你如何在本地环境中部署和调试 Misskey 项目。无论你是想贡献代码还是只是想了解 Misskey 的运行机制，这份指南都能帮助你搭建起本地开发环境。

## 前置要求

在开始之前，请确保你的系统已经安装了以下软件：

1. **Node.js** - 必须使用 20.10.0+ 或 22.x 版本（**注意：当前不支持 Node.js 23.x**）
2. **pnpm** - Misskey 使用 pnpm 作为包管理工具
3. **Git** - 用于克隆代码库
4. **PostgreSQL** - 数据库，版本 15+
5. **Redis** - 用于缓存和任务队列
6. **FFmpeg** - 用于媒体处理（可选，但推荐安装）

## 部署方式

Misskey 提供了多种本地部署方式，你可以根据自己的需求选择合适的方式：

### 方式一：使用 Docker Compose 运行数据库服务

这种方式只使用 Docker 来运行数据库和 Redis，而 Misskey 本体则在本地直接运行，适合大多数开发场景。

1. 克隆代码库：
```bash
git clone https://github.com/misskey-dev/misskey.git
cd misskey
```

2. 创建Docker环境配置文件：
```bash
mkdir -p .config
```

创建 `.config/docker.env` 文件并设置数据库环境变量：
```
# 数据库设置
POSTGRES_PASSWORD=postgres
POSTGRES_USER=postgres
POSTGRES_DB=misskey
```

3. 使用 Docker Compose 启动数据库和 Redis：
```bash
docker compose -f compose.local-db.yml up -d
```

4. 安装项目依赖：

首先确保你的 Node.js 版本正确，Misskey 目前要求 Node.js 20.10.0+ 或 22.x 版本：
```bash
# 检查当前Node版本
node -v

# 如果版本不符合要求，请安装兼容版本
# 使用nvm (Node Version Manager)
nvm install 20.10.0
nvm use 20.10.0

# 或者使用n
n 20.10.0

# 或者直接从官网下载安装包
```

然后安装依赖：
```bash
pnpm install
```

5. 创建配置文件：
```bash
cp .config/example.yml .config/default.yml
```

6. 编辑配置文件 `.config/default.yml`，设置数据库连接信息：
```yaml
# PostgreSQL 配置
db:
  host: localhost
  port: 5432
  db: misskey
  user: postgres
  pass: postgres

# Redis 配置
redis:
  host: localhost
  port: 6379
```

7. 初始化数据库：
```bash
pnpm migrate
```

8. 构建并启动开发服务器：
```bash
pnpm dev
```

9. 访问 `http://localhost:3000` 即可使用 Misskey。

### 方式二：使用 Dev Container

如果你使用 VSCode，可以利用 Dev Container 功能快速搭建开发环境：

1. 确保 VSCode 安装了 "Dev Containers" 扩展
2. 克隆代码库并用 VSCode 打开
3. 当提示时选择 "Reopen in Container"，或手动点击左下角图标选择 "Reopen in Container"
4. Dev Container 会自动安装所有依赖并设置环境，包括：
   - 安装依赖
   - 复制配置文件
   - 构建项目
   - 初始化数据库

5. 一切就绪后，在容器内终端运行：
```bash
pnpm dev
```

### 方式三：手动安装所有组件

如果你希望完全控制所有组件，可以在系统上手动安装所有依赖：

1. 安装并配置 PostgreSQL
2. 安装并启动 Redis
3. 安装 FFmpeg
4. 克隆并设置 Misskey（同上述步骤）

## 开发与调试

启动开发服务器后，Misskey 提供了多种功能来帮助开发和调试：

1. **代码热重载**：修改后端代码后会自动重新构建并重启服务
2. **Vite HMR**：前端代码支持热模块替换，修改后无需刷新页面
3. **Debug 模式**：在浏览器控制台设置 `localStorage.setItem('debug', 'true')` 可启用调试模式

### 日志与调试

- 开发服务器运行时会在控制台输出详细日志
- 前端调试可以使用浏览器开发工具
- 后端日志在开发模式下会输出到控制台

### 常见问题

1. **Node.js 版本不兼容**：Misskey 要求 Node.js 20.10.0+ 或 22.x 版本，不支持 23.x。如果看到"Unsupported environment"错误，请切换到兼容的 Node.js 版本
2. **数据库连接失败**：检查 PostgreSQL 是否正常运行，以及配置文件中的连接信息是否正确
3. **端口冲突**：如果 3000 端口被占用，可在配置文件中修改 `port` 字段
4. **编译错误**：确保使用了兼容的 Node.js 版本，并且所有依赖都正确安装
5. **Redis 连接问题**：检查 Redis 服务是否启动，以及配置文件中的连接信息
6. **"env file not found"错误**：运行 Docker Compose 时可能会提示缺少 `.config/docker.env` 文件，按照步骤2创建该文件即可

## 测试

Misskey 提供了多种测试方法：

```bash
# 运行前端测试
pnpm --filter frontend test

# 运行后端单元测试
pnpm --filter backend test

# 运行端到端测试
pnpm --filter backend test:e2e
```

## 构建生产版本

如果你想测试生产环境下的 Misskey，可以构建生产版本：

```bash
pnpm build
pnpm start
```

## 小结

通过本指南，你应该能够成功地在本地部署和调试 Misskey。开发过程中如遇问题，可以参考 Misskey 的官方文档或查看代码库中的 `CONTRIBUTING.md` 文件获取更多信息。

记住，本地开发最常用的命令是 `pnpm dev`，它会启动一个完整的开发环境，包括自动构建、热重载等功能，让你能够方便地进行开发和调试。
