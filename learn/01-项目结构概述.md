# Misskey 项目结构概述

Misskey是一个开源、去中心化的社交媒体平台，实现了ActivityPub协议，可以与Mastodon等其他联邦宇宙（Fediverse）实例互通。本文档将介绍Misskey项目的整体结构和技术栈。

## 项目技术栈

Misskey采用了现代化的Web开发技术栈：

### 前端
- **Vue.js 3** - 核心前端框架
- **TypeScript** - 使用静态类型的JavaScript超集
- **SCSS** - CSS预处理器
- **Vite** - 前端构建工具

### 后端
- **Node.js** - JavaScript运行时
- **TypeScript** - 后端也采用TypeScript
- **NestJS** - 后端框架，提供依赖注入和模块化结构
- **PostgreSQL** - 主要数据库
- **Redis** - 用于缓存和实时功能
- **TypeORM** - 对象关系映射工具

### 联邦协议
- **ActivityPub** - 社交网络联邦协议，使不同实例间可以互相交流

## 项目目录结构

Misskey项目使用monorepo结构，主要包含以下目录：

```
misskey/
├── packages/ - 核心包目录
│   ├── backend/ - 后端服务
│   │   ├── src/ - 后端源代码
│   │   ├── test/ - 后端测试
│   │   └── migration/ - 数据库迁移
│   ├── frontend/ - 前端应用
│   │   ├── src/ - 前端源代码
│   │   ├── public/ - 静态资源
│   │   └── vite.config.ts - Vite配置
│   ├── misskey-js/ - JavaScript/TypeScript客户端库
│   └── sw/ - Service Worker代码
├── locales/ - 国际化文件
├── assets/ - 资源文件
├── scripts/ - 各种脚本
└── chart/ - Helm chart部署配置
```

### 前端结构

前端代码位于`packages/frontend/src`目录下：

```
src/
├── components/ - Vue组件
├── composables/ - Vue组合式API
├── filters/ - 过滤器
├── directives/ - Vue指令
├── pages/ - 页面组件
├── stores/ - 状态存储
├── scripts/ - 脚本
├── styles/ - 样式文件
└── types/ - TypeScript类型定义
```

### 后端结构

后端代码位于`packages/backend/src`目录下：

```
src/
├── core/ - 核心业务逻辑
├── models/ - 数据模型
├── server/ - 服务器相关代码
│   ├── api/ - API端点和服务
│   └── web/ - Web服务
├── services/ - 服务实现
├── queue/ - 任务队列
├── remote/ - 远程交互
└── misc/ - 杂项工具函数
```

## 主要模块概述

### 帖子系统（Notes）

Misskey中的帖子称为"Notes"，是平台上最基本的内容单元：
- 支持文本、图片、视频等多种内容
- 支持回复、转发（Renote）和引用
- 支持投票、标签和提及用户

### 用户系统

用户系统负责身份验证、授权和用户信息管理：
- 注册、登录和账户管理
- 用户资料、头像和横幅
- 多因素认证和安全功能

### 时间线系统

时间线系统聚合和展示内容：
- 主页时间线（Home）
- 本地时间线（Local）
- 社交时间线（Social）
- 全局时间线（Global）

### 联邦系统

联邦系统实现ActivityPub协议，使实例能与其他联邦宇宙服务互通：
- 远程用户发现和互动
- 内容同步和分发
- 协议适配和转换

### 通知系统

通知系统处理用户间的互动提醒：
- 回复和提及通知
- 点赞和转发通知
- 关注和关注请求通知

## 构建和部署

Misskey使用pnpm作为包管理工具，支持多种部署方式：
- Docker容器
- 手动部署
- Kubernetes（通过Helm chart）

## 结语

Misskey是一个功能丰富的社交媒体平台，采用了现代化的技术栈和模块化的架构设计。这种设计使得系统具有良好的可扩展性和可维护性，适合进行二次开发和定制。在后续文档中，我们将深入探讨各个模块的实现细节。
